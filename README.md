# Fitness With Libby

Marketing site and class-booking system for a women-only fitness studio in Beit
Shemesh. Next.js (App Router) + TypeScript, with Airtable as the backend and
Vercel for hosting.

Live: **https://www.fitnesswithlibby.org**

## Running locally

```bash
npm install
npm run dev
```

Copy `.env.example` to `.env.local` and fill in the values first — the booking
pages fail gracefully without them, but nothing will actually save.

## Environment variables

All of them are documented in `.env.example`, including how to obtain each one.
The same values must be set in **Vercel → Settings → Environment Variables** for
Production and Preview.

Variables are read at build time, so after changing one in Vercel you have to
**redeploy** — an existing deployment keeps the old value with no error.

| Variable | Purpose |
|---|---|
| `AIRTABLE_TOKEN` | Personal access token for the booking base |
| `AIRTABLE_BASE_ID` | Which base to read and write |
| `ADMIN_PASSWORD` | Password for the `/admin` studio dashboard |
| `NEXT_PUBLIC_SITE_URL` | Canonical public URL; drives the sitemap, canonical tags and share cards |

## Deploying

Pushing to `main` triggers a production deploy via Vercel's GitHub integration;
it's live in about a minute. Every other branch gets its own preview URL.

None of this is visible in the repo — there's no `vercel.json` and no workflow
file — so this README is the only record of it.

The canonical host is **www**; the apex redirects to it. `NEXT_PUBLIC_SITE_URL`
must match that exactly, or search engines index two copies of every page.

## Images

Full-size originals live in `assets/source/` and are never deployed. The served
files are `public/*.webp`, generated by:

```bash
node scripts/optimize-images.mjs
```

Rerun it after replacing any source image. Each output is resized to twice its
largest CSS display width — that pipeline is what took Lighthouse performance
from 76 to 100, so don't drop raw exports straight into `public/`.

## Layout

| Path | What it is |
|---|---|
| `app/page.tsx` | Homepage; sections live in `app/components/Sections.tsx` |
| `app/book/` | Class schedule and booking flow |
| `app/admin/` | Libby's roster, members and attendance dashboard (password-gated, not indexed) |
| `app/api/` | Booking, membership, contact and admin endpoints |
| `app/lib/airtable.ts` | All Airtable reads and writes, with caching |
| `app/site.ts` | Canonical URL and business details — single source of truth for SEO |
| `app/globals.css` | Design tokens and every style, ported from the approved design |

## Airtable

Three tables: **Sessions** (recurring class slots), **Booking** (sign-ups) and
**Members**. One row per recurring class *time*, not per date — dates are
computed in code, so the schedule doesn't need maintaining by hand.

Reads are cached (60s for bookings, 600s for sessions) and busted on write, to
stay inside the free plan's ~1,000 API calls per month. Libby manages the studio
through Airtable grid views and the `/admin` dashboard.

## SEO

`app/site.ts` feeds `metadataBase`, the sitemap, canonical tags, the JSON-LD
business listing and the generated share card in `app/opengraph-image.tsx`.

After any change to the metadata, share the live URL into WhatsApp and check the
preview card — it exercises `metadataBase`, the Open Graph block and the image
in one go.

Run the pre-launch audit any time:

```bash
node ~/.claude/skills/nextjs-site-launch/scripts/audit-site.mjs
```
